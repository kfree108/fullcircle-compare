Amazon A+ Content Image Sizes: Why There's No Single Answer

Updated 2026-08-21 · 1426 words · Written against what currently ranked for “amazon a+ content image sizes”
The short answer

A+ Content has no one image size — each of the roughly dozen module templates (full-width banner, three-image row, comparison chart, brand logo) has its own dimensions, and Amazon has changed specific pixel values between template refreshes. The reliable source is the live upload prompt inside the module you're building, not a fixed chart.

Why a fixed size chart goes stale

Search "A+ Content image sizes" and you'll find dozens of charts quoting exact pixel dimensions for every module — 970×300 for a header, 300×300 for a three-image row, and so on. Several of those numbers are right at the moment they're published and wrong six months later, because Amazon periodically revises template dimensions as it changes how A+ Content renders on newer mobile layouts. A chart that was accurate when written isn't a promise it stays accurate, and using a stale dimension produces one specific failure: the upload succeeds, but the image gets cropped or stretched by Seller Central's renderer to fit the current template, which looks worse than a correctly-sized image every time.

The structure that doesn't change, even when the numbers do

What stays stable across revisions is the module shape, not its exact pixel count. Full-width header and full-width tall modules are wide-aspect banners meant to be seen in one glance. Multi-image rows (three-image, four-image) are near-square tiles meant to be scanned side by side, so their individual images need consistent cropping to each other even more than they need an exact pixel match to any chart. Comparison-chart columns are tall and narrow, built for stacked product attributes rather than a single hero shot. Brand logo modules are wide and short, sized for a wordmark, not a product photo. Knowing the shape a module is built for lets you source and crop photography correctly even before you've opened Seller Central to confirm the exact current number.

Where the real number lives

The single reliable source for a module's current pixel requirement is the upload dialogue inside the A+ Content manager itself, at the moment you select that specific template — Seller Central states the exact required and recommended dimensions right there, before the upload. That number is guaranteed current because it's generated from the same system that will render the image; a third-party chart, however recently published, is a snapshot that can lag a template change by weeks or months. The practical workflow: build the module shell first, note what Seller Central asks for on that specific slot, then source or crop the image to match — not the reverse.

A worked example: the same photo, wrong module

Take a 2000×2000 pixel square product photo — perfect for a standard listing's main image. Drop that same file into a full-width header module built for a roughly 3:1 wide-aspect banner, and Seller Central will either reject it outright or auto-crop it, typically cutting the top and bottom off a square image to force the wide aspect ratio, which on a product photo often means slicing through the product itself. The fix isn't resizing the same square file — it's shooting or cropping a genuinely wide-aspect version with the product composed for that shape, which is a different photography decision made at the shoot, not a resize made after.

This is the most common single mistake we see on new A+ Content builds: a brand hands over its existing standard-listing photo set, assuming it can be repurposed directly into A+ modules, and half the shots are the wrong shape for the module they're meant to fill. Budgeting for A+-specific photography or crops at the same time as the standard image shoot avoids a second, more expensive reshoot later.

File size and format limits are more stable than pixel counts

While exact pixel dimensions shift between template revisions, the outer constraints move less: A+ Content images are capped around 2MB per file (some modules allow slightly more), accepted in standard web formats, and Amazon rejects images that are visibly blurry, pixelated, or have jagged edges regardless of whether the pixel count technically clears the minimum. A photo that's correctly sized but poorly compressed will often pass the automated check and still look bad on the page — file size compliance isn't the same as quality, and it's worth judging the rendered result, not just the checkbox.

The other constant across every revision is aspect ratio tolerance: Seller Central's uploader is generally forgiving of a few pixels either side of its stated minimum, but not forgiving of the wrong shape entirely. A near-square image dropped into a wide banner slot fails or crops badly regardless of exact pixel count; a correctly-shaped image a little off the stated dimension usually scales cleanly. Getting the aspect ratio right at the photography stage matters more than hitting an exact pixel figure later.

When the wrong size actually gets a module rejected

An undersized or wrong-aspect image doesn't always get rejected outright — Amazon's uploader often accepts it and quietly scales or crops to fit, which is worse than a rejection because there's no error to notice and fix. The failure shows up later, as a soft or oddly cropped image live on the page that nobody flagged during the build. The safer habit is checking the module in preview mode at actual size before submitting for approval, not just confirming the file uploaded without an error message — the upload succeeding and the image looking right are two different checks, and only one of them is automatic.

Building this into a repeatable process

Getting one module's dimensions right is a five-minute check. Getting it right across every module, every ASIN, on a catalogue that launches new variants monthly — and staying current when Amazon revises a template mid-year — is a maintenance process, not a one-time task. Full Circle has managed more than $500M in Amazon spend across 100+ brands, and the catalogue teams on that book rebuild this check into every A+ Content refresh rather than relying on a saved reference chart, specifically because a stale chart from a previous project is the single most common cause of an image getting silently cropped wrong.

Which one you should actually pick

Don't build a saved reference chart into your workflow — build the habit of checking the live upload prompt for the specific module instead. It costs nothing extra and it's the only version of the number that's guaranteed current the day you're uploading. If you're managing this across a large catalogue where the same mistake gets repeated by different people, the process fix is worth more than any individual number ever will be.

Common questions

What's the correct pixel size for A+ Content images?

It depends on which module you're building, and the exact number can change between template revisions. Check the upload dialogue inside the specific module in Seller Central at the time you build it — that's the only source guaranteed to reflect the current requirement.

Why did my A+ image get cropped after upload?

Almost always because the source image's aspect ratio didn't match the module's shape — a square photo dropped into a wide banner module, for example. Seller Central auto-crops to force the fit rather than rejecting outright, which is worse because the crop can happen through the middle of the product.

Is there a maximum file size for A+ Content images?

Yes, A+ images are capped at roughly 2MB per file, with some modules allowing slightly more. Passing that limit doesn't guarantee quality, though — a correctly-sized but heavily compressed image can still render poorly, so check the rendered result, not just whether the upload succeeded.

Do A+ Content image sizes differ between Basic and Premium?

The shared module types (image headers, comparison charts) use the same dimensions on both tiers. Premium adds module types Basic doesn't have at all — video and interactive hotspot formats — which carry their own separate size and format requirements rather than variants of the Basic dimensions.

Should I keep a reference chart of A+ image sizes for my team?

A rough internal guide for aspect ratio and shape is useful for briefing photographers. Treat exact pixel numbers on it as provisional and re-check them against the live upload tool before a final export, rather than working from the saved chart as if it were current on every project.
